# Instructions for AI coding agents

Read [AI_CONTEXT.md](AI_CONTEXT.md) before making changes. For a subsystem with its own guide, read that guide too; the snapshot subsystem's guide is [pylizlib/core/os/snap/README.md](pylizlib/core/os/snap/README.md).

## Project conventions

- This is a Python library. `pyproject.toml` requires Python 3.12 or later; use `uv` for the project environment and commands.
- Inspect the implementation, its callers, and nearby tests before changing behavior. Keep changes scoped to the requested task.
- Treat public imports, function signatures, serialized JSON, archive formats, and documented failure behavior as compatibility contracts. Check compatibility adapters and legacy tests before removing or changing them.
- Add or update tests for behavior changes. Put module-level tests under the corresponding `test/core` path; put multi-module workflows using public APIs under `test/integration`.
- Use generated local fixtures for deterministic tests. Avoid network access unless the task explicitly requires it; optional AI and media tests may need extras, models, or network access.
- Follow Ruff settings in `ruff.toml` (line length 200; lint selections E, F, I). Public APIs use typed Google-style docstrings; preserve that style when editing documented code.

## Filesystem and snapshot safety

- Snapshot operations can replace or remove user data. Follow the existing path validation, containment, symlink, staging, transaction-journal, recovery, and post-commit cleanup rules. Do not bypass them with direct filesystem operations in production code.
- Keep operation boundaries clear: `catalogue.py` and `manager.py` are public facades; operation algorithms belong in `operations/`; persistent layout and recovery belong in `storage/`; reusable OS primitives belong under `pylizlib/core/os/`.
- Test destructive snapshot flows only in isolated directories. Snapshot safety checks can reject OS-managed temporary directories as critical destinations. The integration fixture uses a unique child of `test_local/snapshot_integration`; remove only the workspace created by the current test. Never delete the shared `test_local` directory.
- Do not assume local rename, flush, permissions, or durability behavior proves the same guarantee on SMB/NFS. Keep platform-specific behavior explicit and covered by the appropriate platform tests.
- Symlinks and junctions are rejected by snapshot tree operations. Do not add traversal through them without an explicit policy and regression coverage.

## Useful commands

Install development dependencies:

```sh
uv sync --group dev
```

Run snapshot unit and integration tests:

```sh
uv run pytest test/core/os/snap test/integration/snap -q
```

Run the broader shared filesystem and text contracts:

```sh
uv run pytest test/core/test_documentation_contracts.py test/core/os/snap \
    test/core/os/filesystem test/core/os/paths test/core/data/text -q
```

Run repository quality checks with `make lint` and `make format-check`. `make test` runs the configured full suite and enables the media extra. The integration suite can also be pointed at a mounted filesystem with `./test/integration/snap/run.py --root /path/to/mount`.

## Local and generated files

- `test_local/` and `temp_local/` are ignored, user-local work areas. Never treat their contents as disposable project-wide state.
- `.env` is ignored and may contain credentials. Do not print, copy, or modify its contents unless the task explicitly requires it.
- API documentation generated by `make docs` goes under `docs/api`; the focused snapshot preview from `make docs-snap` goes under `temp_local/docs_snap_preview`.
